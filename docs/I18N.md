# Translating Beebo (desktop app)

Beebo's desktop screens can be shown in English, Spanish, French, German, Brazilian Portuguese and
Italian, and the layer underneath is built so adding a language is a file copy. There is no
translation library: the whole thing is `src/lib/i18n.js` (about 250 lines, no dependencies).

## How it works

- `src/locales/en.json` is the **source of truth**. Every other `src/locales/<code>.json` has the
  same keys. Files are picked up automatically at build time.
- A screen calls `const { t } = useI18n()` and writes `t('nav.movies')`.
  Outside React use `import { t } from '../lib/i18nApp.js'`.
- A key missing from the chosen language shows the **English** text (so a half-finished language
  is usable); a key missing everywhere shows the key itself, and in development a warning is logged.
- The language is chosen in **Settings > Language**: "Automatic" follows the Windows display language
  (asked from the main process, `app:systemLanguages`), or pick one. It applies at once and is
  remembered in `localStorage` (`beebo.language`). `<html lang>` and `dir` follow it.
- Only the *interface* is translated. Movie titles, descriptions and cast come from TMDB in the
  language chosen under Settings > Metadata, and file names are never touched.

## Message syntax

```json
{
  "nav.movies": "Movies",
  "library.showingOnly": "Showing {label} only",
  "detail.votes": { "one": "{count} vote", "other": "{count} votes" },
  "library.resultsCount": { "=0": "No movies", "one": "{count} movie", "other": "{count} movies" },
  "firstrun.moreFoldersNote": "New installations keep everything under <code>C:\\Beebo</code>.",
  "library.cleanNamesTvHint": "... '{{Show Name}} S{{season}}E{{episode}}' ..."
}
```

| Syntax | Meaning |
| --- | --- |
| `{name}` | value of `vars.name`, left as written when missing so the gap is visible |
| `{n:number}` `{p:percent}` | formatted for the language (1,234 / 1.234; 42 %) |
| `{when:date}` `{when:time}` `{when:datetime}` | date / time formats for the language |
| `{{` `}}` | a literal `{` or `}` |
| object value | plural entry: `zero one two few many other`, or `"=0"` for an exact match. Chosen with `Intl.PluralRules`. `{count}` is formatted as a number automatically. `other` is required. |
| `<b>` `<em>` `<code>` | the only markup allowed; render with `rich()` from `components/Rich.jsx` (React nodes, never HTML strings) |

Helpers on the object `useI18n()` returns: `t(key, vars)`, `tOr(key, fallbackText, vars)` (for
text that comes from data, e.g. a tab another module added), `n(number, options)`,
`d(date, style | options)`, `dur(minutes)` ("2 hr 28 min", "2 Std. 28 Min."), `list(items)`,
`listParts(items)`, `rel(-3, 'day')`, `compare(a, b)` (locale-aware sort), `locale`, `dir`.

Use the language's own number, date and list formats through these, not `toLocaleString()` with no
locale: in the packaged app Chromium reports only the language it shipped resources for.

## Key naming

`area.thing` in lower camel case: `nav.*` (sidebar), `sidebar.*`, `footer.*`, `logout.*`,
`library.*` (Movies / TV toolbar and cards), `view.*` and `viewmode.*`, `detail.*`, `settings.*`,
`language.*`, `firstrun.*` (Get Started), `doctor.*`, `a11y.*`, `common.*`. Keys ending in a
variable (`nav.${id}`, `firstrun.step.${id}`) are fine, the report understands `t(\`prefix.${x}\`)`.
Write whole sentences, never build one from pieces (word order differs); pass the pieces as `{vars}`.

## Adding or changing a string

1. Add it to `src/locales/en.json` and use it with `t('...')`.
2. `npm run i18n:report` (in `desktop/apps/desktop`) lists what every language is missing. They
   show English until translated, so this never blocks a release.
3. Translate it in the other files. **Write your own translations**; do not copy text from other
   products.

`npm run i18n:report -- --verbose` prints each missing key with its English text, `-- --lang=fr`
limits it to one language, `-- --strict` exits 1 on anything missing, broken, unused or undefined
(for CI). `test/i18n.test.js` already fails the suite for: a key in code but not in `en.json`, a
key in `en.json` that nothing uses, a shipped language whose placeholders, plural forms or markup
differ from English, or a language that is mostly copied English.

## Adding a language

1. Copy `en.json` to `<code>.json` (`ja.json`, `pt-PT.json`). It appears in Settings > Language
   with its own name (add it to `NATIVE_NAMES` in `src/locales/index.js` if the platform's name
   for it is not what you want).
2. Translate the values. Keep placeholders, markup tags and product names.
3. `npm run i18n:report -- --lang=ja` until missing / extra / broken are 0.
4. Add the code to the `SHIPPED` list in `test/i18n.test.js` when it is complete.

Regional files fall back by language: `pt-PT` users get `pt-BR` until a `pt-PT.json` exists.

### Right-to-left (Arabic, Hebrew, Persian, Urdu)

The switch is done: choosing one sets `<html dir="rtl">`, and `a11y.css` mirrors the shared pieces
(sidebar, nav highlight). Most screens still use physical `left` / `right` and fixed `flex`
directions in inline styles, so plan a pass converting those to logical properties
(`margin-inline-start`, `inset-inline-end`, `text-align: start`) before shipping an RTL language.

## What is translated today

Sidebar and window frame, the What's new and log-out dialogs, Movies and TV Shows toolbar, tabs,
filters, poster cards and empty states, the View options and the library view switcher, the movie
details page, Settings (top level and Language), Get Started (all steps and the folder / poster
finder) and the Connection Doctor window.

| Language | Keys |
| --- | --- |
| English (source) | 395 |
| Spanish (es), French (fr), German (de), Portuguese - Brazil (pt-BR), Italian (it) | 395 each |

## Not translated yet

- Release notes ("What's new") are English data in `App.jsx`.
- The Connection Doctor's check names, results and phone advice (`lib/connectionDoctor.js`), the connection test wizard and `RESULT_TEXT` in `lib/connectionModel.js`.
- Movies / TV pop-up windows (fix the match, review a USB folder, clean up names, actors, sequels, duplicates), the library table and filter / saved-view menus, the person page and metadata editor.
- Every other screen (sign-in, Upload, Admin, Dashboard, Users, History, Flags, Converted, Missing Files, Switch to Beebo, Audiobooks, Live TV, Phone Backups, Playlists, BeeboSchool, Home Game Server) and the Settings panels below the top level.
- Native things owned by Electron: window menus, tray, the installer, error dialogs from the main process.
- Pure formatters in `lib/movieFormat.js` and `lib/firstRun.js` keep their English originals (tests cover them); the screens use the translated twins (`dur()`, `lib/firstRunI18n.js`).

## The web pages (plan, not built)

The browser pages the desktop app serves (`page()` in `electron/streamServer.js`, navigation in
`electron/browserChrome.js`) are **not** wired yet, because there is no simple hook:

- `page(body)` receives a finished HTML string with English text written inline in about 3,000
  lines of template literals, and has no access to the request, so it cannot know the visitor's language.
- `<html lang="en">` is hard-coded (`page()` and two other document builders).

Proposed path, smallest first:

1. **Language per request.** Read `Accept-Language` (and a `beebo_lang` cookie set by a small picker in the page footer) in the route handler that calls `page()`, and pass `{ lang }` to it. `page()` sets `<html lang dir>` from it.
2. **Chrome first.** Move `browserChrome.labels`, the sidebar section titles ("YOUR LIBRARY", "MORE FROM BEEBO"), the mobile tab names and the footer text into a `web.*` namespace in the same `src/locales/*.json` files, and give `browserChrome` a `t` from a Node build of `i18n.js` (it is dependency free and already CommonJS-importable with `import()`); load the catalogs with `fs.readFileSync`.
3. **Pages one at a time.** Replace literal text in a route with `t('web.movies.search')`; unconverted pages keep working because a missing key falls back to English.
4. **Guard.** Extend `i18n:report` to scan `electron/*.js` for `t('web.` keys, and add a test that renders each converted page in `de` and asserts no `{placeholder}` or key leaks.

Do this after `streamServer.js` stops changing quickly; it is the file every other feature touches.
